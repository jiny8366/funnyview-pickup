각 항목의 옵션을 시각 예시로 비교하고, 원하는 표준에 ✅ 체크하세요. 초록 테두리 = 현재 확정/권장 표준(최신). 선택 후 이 파일 그대로 회신해 주시면 그대로 구현합니다.

원칙: 이미 확정된 공용 표준으로 outlier 수렴 (확정한 것은 변경하지 않음). "최신/장점"은 공용 컴포넌트가 단일 소스라 색·문구·동작이 안 갈리고 중복 드리프트 버그가 사라지는 점입니다.

1. 숫자 변경 컨트롤

정합성·UX

수량·단가·안전재고 등 숫자 편집. 같은 기능에 3가지 방식이 혼재.

권장: 리스트/표 셀 = A(InlineNumberCell). 바코드 스캔처럼 즉시입력이 필요한 특수 입력만 B/C 유지.

2. 상태 뱃지 / 라벨 맵

정합성 버그

같은 상태가 화면마다 다른 색·문구로 표시됨 (예: 동일 주문이 "배송 중" vs "출고"). 라벨 맵이 6~수곳 중복 정의.

같은 "received(입고완료)" 가 화면마다: 입고완료 vs 입고완료(emerald) vs 라벨만
중복 라벨 맵: ORDER_STATUS_LABEL(2), 발주 STATUS_LABEL(3), CYCLE_LABEL ×5, LENS_TYPE_LABEL ×4

3. 문서 출력 / 인쇄

대부분 수렴

거래명세서·송장·픽리스트 출력 방식.

4. 버튼

시각 불일치

같은 의미(확정/취소/삭제)에 서로 다른 색·모양. 공용 <Button> vs raw <button>.

5. 페이지 헤더

포털 톤차이

6~8. 검색입력 · 필터 · 빈 상태

6. 검색 입력

현재 9종(테두리·아이콘·Enter vs 실시간 제각각)

7. 필터 UI
전체입고출고

칩·toggle·탭·드롭다운 혼재

8. 빈 상태
데이터가 없습니다

<td>텍스트 vs 컴포넌트 혼용

권장 구현 순서

  1. Phase 1 (정합성, UX 변화 없음): 2번 상태/라벨 맵 단일소스 통합 — 버그 제거, 화면 그대로. 가장 가치 높음.
  2. Phase 2 (확정표준 적용): 1번 숫자→InlineNumberCell(M3 #383 3곳), 3번 잔여 인쇄버튼 표준화.
  3. Phase 3 (고객 UX 영향, 다파일): 4 버튼·5 헤더·6 검색·7 필터·8 빈상태 점진 수렴.
